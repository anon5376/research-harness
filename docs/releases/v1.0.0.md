# Research Harness v1.0.0 — release draft

Research Harness brings GPT Pro, Codex cloud and local jobs into one place. Use New job to choose a route, watch work on the board, and answer requests in the inbox. On a Mac, the local route is called This Mac and runs a shell command. A cloud job marked done can be saved to a local branch.

For GPT Pro, copy the job's prompt into a chat and paste the reply back into the harness. The saved reply is the result. Codex cloud can launch through the CLI when its environment is available there; a web handoff lets you launch and link a task by hand when needed. Cloud results are collected and checked locally before landing.

## Main commands

Run these from the repository; replace the placeholders with your own values.

| Command | Purpose |
| --- | --- |
| `bin/rh job add <contract>` | Add a job from a TOML contract. |
| `bin/rh job show <job>` | Show a job, its events and receipt. |
| `bin/rh job cancel <job> --reason <reason>` | Cancel an unstarted or stalled job. Cancelling does not stop a stalled task or process; stop it separately if still running. |
| `bin/rh status` | See jobs, stops, routes and inbox items. |
| `bin/rh inbox` | See operator steps, refusals and decisions. |
| `bin/rh serve` | Open the dashboard and its everyday actions. |
| `bin/rh supervise` | Run the supervisor's check loop. |
| `bin/rh chat prompt <job>` | Print a GPT Pro job's prompt. |
| `bin/rh chat reply <job> <file>` | Save the reply as the job result. |
| `bin/rh cloud handoff <job>` | Hand off a ready cloud job for a manual launch. |
| `bin/rh cloud prompt <job>` | Print the prompt for a cloud handoff. |
| `bin/rh cloud attach <job> <task>` | Record the manually launched task. |
| `bin/rh cloud harvest <job> <patch>` | Hand a saved patch to the supervisor for collection. |
| `bin/rh land <job>` | Commit a done cloud job's diff to a local `cloud/<job>` branch; it does not push. |
| `bin/rh env spec` | Print the steps for creating a cloud environment. |
| `bin/rh config set cloud.env_id <id>` | Set the cloud environment ID. |
| `bin/rh lease run --what <label> -- <command>` | Run a command under the heavy-step lease after host admission. |
| `bin/rh doctor` | Check the health of surfaces the harness depends on. |

`bin/rh --help` lists all command groups; each group has its own help.

## Desktop packages

The build workflow is configured to produce Apple silicon and Intel macOS disk images and a Windows x64 executable. The macOS builds are ad-hoc signed; the Windows build is unsigned. These signing descriptions are workflow requirements, not confirmation that v1.0.0 packages have been built or opened.

On macOS, mount the disk image and copy Research Harness.app to Applications. If macOS blocks it, use System Settings → Privacy & Security → Open Anyway. On Windows, run the executable; if SmartScreen blocks it, choose More info → Run anyway. The Windows window needs the Edge WebView2 Runtime.
